# 1. 锁定技术决策

## 1.1 坐标系

文档设计语义使用：

```text
X = 横向
Y = 平面前后
Z = 高度
```

但 Godot 使用 **Y-up**。当前项目锁定映射：

```text
doc(x, y, z) -> Godot(x, z, y)
```

因此：

```text
Doc Floor 0 = Z 0
Doc Floor 1 = Z 3

Godot Floor 0 = Y 0
Godot Floor 1 = Y 3
```

高度永远是真实空间高度，不是 Render Layer。

---

## 1.2 渲染方向

锁定：

> **Real 3D World + Orthographic Camera + 2D Pixel Characters + Pixel-art Surface + Stylized Lighting**

当前约束：

| 层 | 决策 |
|---|---|
| 世界位置 | 真 3D |
| 楼层 | 真 3D 高度 |
| 墙 / 楼板 | 真 3D Mesh + Collider |
| 光照 | 真 3D |
| 摄像机 | Orthographic |
| 角色 | 2D Pixel Sprite / Billboard |
| 表面 | Pixel-art Texture / Nearest |
| 输出基准 | 640×360，再整数缩放 |

核心思想：

> **用 3D 解决空间问题，用 Pixel Art 解决视觉问题。**

---

## 1.3 建筑不是 Prefab，Terrain 也不是 Tile

两个底层原则：

```text
Terrain = Material Field
Building = Structural State
```

不是：

```text
Terrain = 大 Tile 图片
Building = 一栋预制房子
```

---

## 1.4 所有玩家编辑操作都先变成 Intent

任何直接操作 Mesh 的设计都禁止成为正式架构。

统一流程：

```text
Player Input
    ↓
Intent
    ↓
State Mutation
    ↓
Spatial / Rule Analysis
    ↓
Generator
    ↓
Runtime World
```

例如：

```text
DRAW_WALL
MOVE_WALL
DELETE_WALL
CLEAR_TERRAIN
DIG_TERRAIN
FILL_TERRAIN
DRAW_ROAD
PLACE_OBJECT
MOVE_OBJECT
ROTATE_OBJECT
ADD_OPENING
```

# 5. TerrainChunk 与多尺度 Terrain

## 5.1 Chunk

世界必须切分 Chunk：

```text
World
├── Chunk_0_0
├── Chunk_0_1
├── Chunk_1_0
└── ...
```

Chunk 是：

- 内存管理单位。
- 更新单位。
- Dirty Region 的边界。
- 保存 / 加载单位。
- Terrain Mesh 重建单位。

---

## 5.2 FineGrid

FineGrid 不是屏幕像素，也不是建筑 Grid Snap。

它只是 Terrain 内部的离散计算单位。

玩家看到的是连续空间：

```text
Vector3 / Polygon / Spline
```

Terrain 内部计算可以是：

```text
Cell[0]
Cell[1]
Cell[2]
...
```

因此两者可以共存：

```text
Continuous World
        │
        ▼
Terrain Rasterization
        │
        ▼
FineGrid
```

# 12. BuildingPlacementValidator

建筑放置前必须询问 Terrain：

```gdscript

```

检查：

```text

2. 坡度是否允许？
```


# 21. T-Junction 必须作为正式规则处理

已实现验证的 Bug：

> 墙的一端落在另一面墙的中间，只判断“共享端点”会破坏 Planar Graph。

正式规则：

```text
任何落在线段内部的 Node
        ↓
Split Segment
        ↓
形成真正的 Planar Subdivision
```

这个规则必须保留。

因为它是：

```text
Wall Connection
    ↓
Room Detection
    ↓
Procedural Fusion
```

的基础。

# 22. Wall Connection Solver

两个 Wall 在连接处不能出现厚度缺口。

解决方案：

```text
Joint
  ↓
Extend each wall by half thickness
  ↓
Meshes overlap
  ↓
Corner appears solid
```

已验证 corner 从不实心到实心的自动求解。

未来可以扩展：

```text
Miter Join
Bevel Join
Corner Block
Beam Joint
Trim
```

第一版优先稳定，不追求复杂几何。

# 24. Openings：门窗都是 Wall 属性

不能把 Door 当作一个独立洞口去修改 WallGraph。

正式结构：

```text
Wall
└── Openings
    ├── Door
    └── Window
```

Wall Generator 根据 opening 分割自己的几何体。

### Door

```text
下部：开放
上部：Lintel / Wall
```

### Window

```text
中部：开放
下部：Sill
上部：Wall
```

这样：

- Door 可以通行。
- Window 可以看到 / 透光。
- NPC 不会穿窗。
- Room topology 不需要额外“补边”。

# 25. Room Detection

Room 不是玩家手工填写的主结构。

它由：

```text
Floor
+

```

推导。

流程：

```text

    ↓
Planar Subdivision
    ↓
Face Traversal
    ↓
Closed Regions
    ↓
RoomState
```

当前已经验证：

```text
8 × 6 = 48 m²
```

房间能够正确生成，并且 T-Junction 修复后，切墙会自动把一个房间变成两个房间。

# 34. 材料消耗：建筑不再“凭空生成”

这是 V2.1 新增的正式规则。

建造成本必须与几何结构绑定。

例如：

```text
Wall Length = 8m
Height = 3m
Thickness = 0.3m
```

几何体积：

```text
8 × 3 × 0.3 = 7.2 m³
```

Building Definition 再把几何量转换为资源量：

```text
Stone = 720
Wood = 30
Mortar = 50
```

真实代码中不一定使用“1 m³ = 100 units”这样的固定换算，而应由 Material / Building Recipe 定义。

# 52. 统一美术风格的五个控制维度

# 74. 已经暴露过的 Bug 与必须保留的修复规则

## 74.1 Stuck Detection

不能把“走得久”直接当作“被卡住”。

只在：

```text
Agent not moving
```

时累积 stuck time。

---

## 74.2 Ramp Collider

坡道必须从低端进入，且顶部必须有 Landing。

---

## 74.3 Floor Collision

楼板是真正的 Collider，不能只是渲染表面。

---

## 74.4 Arrival Check

走完 waypoint != 到达。

最终：

```text
distance(actual_position, target)
```

必须满足阈值。

---

## 74.5 Stairwell 两层处理

楼梯口可能在：

- 下层为实体斜坡。
- 上层为楼梯孔。

两个楼层都必须进行正确的障碍判定。

---

## 74.6 InteractionPoint World Transform

InteractionPoint 在 Planning 时必须已经是正确 World Position，不能等待 `_process` 才更新。

---

## 74.7 T-Junction

必须进行 Planar Subdivision。

# 86. 最终架构哲学

> **Spatial 决定世界在哪里。**

> **Data 决定世界是什么。**

> **Rules / Systems 决定世界如何运行。**

> **Renderer 决定世界看起来怎样。**

进一步压缩成：

```text
Spatial
  = Where

Data
  = What

Rules / Systems
  = How

Renderer
  = Appearance
```
