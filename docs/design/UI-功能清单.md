## 四、玩家模式 vs 开发者模式

**核心问题：开发者模式要多出什么。** 我按"你已经有的、但玩家不该看的"列：

| 功能 | 玩家模式 | 开发者模式 |
|---|---|---|
| 顶栏时间 | 显示 | 显示 |
| **坐标 / 楼层 / 是否在地面** | 隐藏 | 显示 |
| **居民的 FSM 状态**（`GOING` / `WORKING`） | 隐藏 | 显示 |
| **路径点 / 当前目标 / `stuck` 计数** | 隐藏 | 显示 |
| **`last_status` / `last_rejection`** | 只在被拒时提示 | 常驻显示 |
| **寻路探针 / 遮挡探针**（`--cozy-probe-*`） | 无 | 按钮触发 |
| **实体列表 / id 查询**（`state_of(id)`） | 无 | 面板 |
| **导航网格 / 房间多边形 / 障碍框** | 无 | 可视化叠加 |
| **地形材料 / 可建造性** | 无 | 可视化叠加 |
| **FPS / 绘制调用 / 实例数** | 无 | 显示 |
| **存档 VERSION / 实体计数** | 无 | 显示 |
| 建造工具 | 隐藏（`BUILDING_ENABLED=false`） | 可临时打开 |

## 五、排布之前要你定的（**这些不是 UI 问题，是架构问题**）

| # | 事 | 为什么卡着 |
|---|---|---|
| 1 | **副本用什么相机** | 家园锁死 yaw 180 / pitch 40；近战 ARPG 要另一套。**改相机是项目列的"危险信号"，必须你点头** |
| 2 | **两个世界怎么共存** | 现在是**一个 `main.gd` 建的一整个世界**。第二个世界是换场景？还是同一世界的另一块地？这决定"按 E 传送"怎么写 |
| 3 | **总纲 §82** | Gameplay / World 层写着"Vertical Slice 前冻结"。副本+战斗 = 解冻，要你一句话 |
| 4 | **玩家控制的是谁** | 你的描述像是"玩家自己进"。而项目前提是"晚上**带村里的某个居民**下魔域" —— 是同一个意思吗？（待拍板 B 建议：从居民里挑） |
| 5 | **家园在副本期间还跑不跑** | 居民的日程、作物生长 —— 停还是继续？这决定存档和时钟怎么切 |

## 六、我的判断（供排布参考）

**配方面板 → 弹窗**：背包/装备/属性这类，游戏里通常是一个键（`I` / `C`）开一个全屏或侧边面板。

**战斗 HUD 要极简**：近战动作游戏里，屏幕上同时能看的东西不超过三样（血、技能冷却、一个敌人）。

**双模式最容易的做法**：**一个 UI 层 + 一个"显示级别"常量**，而不是两套界面。
开发者模式多出来的东西，几乎全是"已经在打印的信息" —— 把它们从 `print` 搬到面板上，
**不新增任何数据来源**。这样两套界面不会漂移，也不会出现"开发者模式里是对的、玩家模式里是坏的"。

**⛔ 我不建议现在做的**：完整的设置菜单、小地图、选档界面。它们和"副本能跑起来"无关。
