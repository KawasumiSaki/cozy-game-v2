# V2-14 · 建筑意图（轮廓 → 结构）

> **状态** ✅ 已完成（2026-09-11）
> **阶段** Phase 3 建筑
> **依赖** V2-17 屋顶生成器 ✅
> **架构依据** 总纲 §17 BuildingSystem 总原则 ｜ §86 第一个完整 Demo
> **代码位置** `building/outline_generator.gd` + `main.gd` 的 outline 工具

## 一句话
玩家画轮廓表达意图，系统自己算出墙、门、房间和屋顶。

## 交付了什么
- **`CozyOutlineGenerator`**：轮廓多边形 → 墙 Intent 列表 + 一道门
  - 门开在**离玩家最近的边**（从你走近的那侧进屋），且该边必须够长
  - 轮廓**闭合**（最后一条边回到起点）—— 这是房间识别能发现房间的前提
- **游戏内 outline 工具**：建造模式下 `TAB` 选到 outline，
  **点击放角点 → `ENTER` 成建 → `ESC` 取消**，带橡皮筋预览
- **失败会说明原因**（地形门禁拒绝时提示，不是静默）

## 验收断言
```
[cozyv2] outline build: 4 pt(s) -> +4 wall(s), +1 room(s), +1 roof(s)  [OK]
[cozyv2] outline room area: 20.8 m2 expected 20.8                      [OK]
```

面积断言是关键：它证明**墙落在图纸说的位置**，而不只是"出现了几面墙"。

## 关键决策
- **生成器只出墙和门，不出房间和屋顶**
  房间来自墙图（V2-06），屋顶来自房间（V2-17）。**它们已经存在，不该在这里重复**。
  这正是总纲"意图进、结构出"链条的含义——下游全部自动跟随。
- **门开在离玩家最近的边**
  从你走近的那侧进屋，而不是"第一条边"。这是提示（hint）不是硬编码。
- **断言用面积而不只是数量**
  "墙数 +4"可以蒙对，"房间面积 20.8 m²"不能——它同时验证了位置。

## 踩的坑（3 个，全部由断言抓出）
1. **`_build_roofs()` 不幂等**
   再调一次会给已有房间**重复叠屋顶**。而它每次建筑变化都会被调用。
   修法：只给还没有屋顶的房间生成。
2. **屋顶规则写成了"最高楼层"，这对独立平房是错的**
   一栋一楼的小屋在它自己的 footprint 上就是最顶层，**必须有顶**。
   正确判据是「**上方有没有东西遮挡**」，不是「在不在最高层」。
3. **"上方有遮挡"只用重心判断，遇到楼梯井就错**
   房子一楼右半边的重心恰好落在楼梯井洞口里，于是被判成"没有遮挡"而加了屋顶。
   修法：**采样房间内部**（重心 + 顶点向重心收缩），多数被遮住才算被遮住。

> 三个 bug 都是"代码看起来对、断言说不对"。第三个尤其典型：
> 单点判断在大多数房间上碰巧是对的。

## 现有状态（如实）
- **只生成墙和一道门**。窗、楼梯、地板仍需手动（总纲 §86 的完整流程里有）
- 门的位置只按"离玩家最近"，没有考虑朝向/采光/地面坡度
- **轮廓自交/凹多边形未做防护**：凹多边形能出墙，但房间识别可能给出意料的结果
- 屋顶在房间多边形变化时**不会重新生成**（幂等跳过），这是脏区问题的延伸
