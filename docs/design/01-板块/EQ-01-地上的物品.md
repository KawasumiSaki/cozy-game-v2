## 一句话

砍树掉木头、打怪掉装备 —— **东西先落在地上，走过去才进包**。

## Willow 的原话（2026-09-15）

> 我们需要做掉在地上的物品这个东西，比方说右键树，砍树，然后会掉下来木头\*4，
> 打怪会掉下来装备，比方说某个小怪掉落 5% 的几率掉钢剑什么的。**我们靠近自动拾取。**

她这句话回答的是"卸下该做什么"（A/B/C 里的 A），但答案比"卸下"大：**它是一个系统**。
所以三条现成的路一起改道：

| 改之前 | 改之后 |
|---|---|
| 砍树 → 木头直接进包 | 砍树 → 地上掉木头 ×4 → 走近自动捡起 |
| 打怪 → 掉落直接进包 | 打怪 → 地上掉出来 → 走近自动捡起 |
| （还没有）卸下 | 卸下 → 同一条路（`_lay_item`，等装备面板落地） |

**`_hand_out` 的三个分支留下来了** —— 它决定"掉什么"，只是终点从背包变成地上。

## 两个载荷，因为是两种东西

素材是 **id + 数量**（`CozyInventory` 的词汇，两块木头是一个数）；装备是**实例**
（带滚出来的词条，两把剑是两把剑，堆叠这种东西不存在）。
`CozyItemContainer` 的头注释为"它为什么不是 `CozyInventory`"写过同一个论证，
这里再出现一次是因为**是同一个分叉**。

## 这条最贵的数：拾取半径被**最短的** reach 卡住

拾取半径就是这套机制的全部。太长 → 每一个掉落都在出现的那一帧被捡走，
`掉在地上` 和 `直接进包` 变成**同一段代码配两句不同的注释**（账本、数字、时刻全都一样）；
太短 → 捡东西变成找像素。**游戏里没有任何别的东西能分辨对的半径和错的半径**，
因为两个世界的结局都是木头在包里。

**上界来自物体表里最短的那个 reach，不是你正在看的那个。**
`_gather_from` 拒绝在超过 reach 的地方动手，而掉落物落在那个物体的**边缘**、
朝玩家那一侧 —— 所以"站在自己 reach 极限上的玩家"和"他刚砍下来的东西"之间的距离
**就是那个 reach**。

```
树 / 石头    reach 1.3
作物         reach 0.8   ← 最短的
```

第一版写的是 **1.0**，因为眼前那个数是 1.3。后果是：**收作物会把小麦直接塞进包，
而砍树会留下东西要走过去** —— 同一套机制两种手感，而且没有任何东西会说。
`test_dropped_item` 对**每一个可采集物体**断言这条关系（不是只对树），
所以下一行短 reach 不能再把它带回来。

现在：**半径 0.6 < 最短 reach 0.8**。

## 装不下，就留在地上

背包有容量、背包（pack）没有，所以**只有一种掉落会被拒绝**。拒绝是
`CozyItemContainer.add_item` 返回 -1，真正重要的是它接下来去哪。

**"收下了又销毁"是玩家唯一会体验成损失的结果**：他看见一把剑掉下来，没地方放，然后它没了 ——
没有解释，也拿不回来。规则是：**装得下才拿，账本确认到了才从地上删**。
它留着，配一句说明，等腾出空位它还在。

两种状态断言看不见的错法：拿了但**不删**（下一帧再拿一次 —— 同一把剑，永远）、
装不下却**删掉**（形状是 bug 的沉默）。两条都断言了，两条都做了改坏实验。

**每帧喊一句"装不下"等于没喊。** `refused` 是每个掉落一个 bool，只置一次，
而且**故意不进存档** —— 它是"这一局已经说过什么"的事实，不是掉落的属性。

## 掉落之间要散开

一次击杀掉 2–3 件，落在同一个点上就是**两件玩家永远看不见的东西** ——
走过去捡起"一件"，三件一起消失。所以按表序散在一个小环上（`DROP_SPREAD` 0.36，
`count <= 1` 不散）。**确定性**的环，不是每次随机：同一个 roll 永远散成同一个形状。

⚠️ 环上两件的最大间距是 `0.72`，**比拾取半径 0.6 宽**。这是有意的：
走过去一件一件捡。断言里"走过去"那一段是**逐个走**的，
站在第一件上就指望捡完，等于断言这个散开没有作用。

## 存档

`drop` 是一个新的**实体 kind**，走 `CozyEntityRegistry` 一行 + `_apply_world` 恢复
（`VERSION 2` 的保存单位是实体列表，所以是加 kind，不是加顶层键）。
位置是**掉落自己拥有的事实**（`at`），transform 是它的视图 ——
`to_global()` 在树外的节点上会报引擎错误，而掉落必须在**没有场景**的地方也能构造、
存档、比较（单元套件就是这么写的）。

活断言 `save/load ground` 在存档往返里放一个**标记掉落**（(-17.5, 0, 9.25) 的 3 块石头），
和标记墙同一个道理：默认世界里没有这个位置的东西。

⚠️ **比较要"读回来"，不要 stringify。** JSON 把每个整数都变成浮点，
写出去的 `0` 和读回来的 `0.0` **作为文本不等、作为数字相等** ——
`CozySaveManager` 开头就写着这句话。第一版就是 stringify 比的，
把一次完全忠实的往返报成了 `(CHANGED)`。修法不是加容差，
是把两份 payload 都过一遍 `apply_dict`，比**两个掉落自己怎么描述自己**。

## 不是家具

`drop` 不进 `objects`，因此不挡路、不提供交互点。居民搬运寻路读的是 `objects`，
掉在地上的剑不该变成一堵墙。

⚠️ **`objects.has(drop)` 不是一个 `false`，是一个 typed-array 错误** ——
`Array[CozyWorldObject]` 的 `has()` 会拿值去校验元素类型。
写那条"它不是家具"的断言时打了两行 `ERROR`，返回值恰好是想要的那个 `false`。
**"恰好对"是这里最危险的一种对。** 已记进 `docs/INVARIANTS.md`（bug 27）。

## 改坏实验（见 `交接.md` 的规矩：没红过的断言不算断言）

**11 条，9 条当场红，2 条绿着 —— 而那 2 条是最值钱的。**

| 改坏 | 结果 |
|---|---|
| 拾取半径 0.6 → 8.0 | 红（2） |
| 砍树改回直接写包 | 红（1）＋ 1 行 `SCRIPT ERROR`（检查越界崩了，已加守卫） |
| 捡到之后不从地上删 | 红（3） |
| **拾取 pass 不看装不装得下** | **绿** → 见下 ① |
| 掉落不注册进实体表 | 红（6） |
| 掉落全部落在同一个点 | 红（1） |
| 读档不清掉旧的掉落 | 红（2） |
| **`to_dict` 不写位置**（冒烟） | **绿** → 见下 ② |
| `to_dict` 不写位置（单元） | 红（2） |
| 没有 id 的掉落被接受 | 红（2） |
| 什么都装得下（容量作废） | 红（2） |

**① 外层 `fits_in` 是纵深防御，坏了不丢行为、只丢"说明"** ——
`collect_into` 自己也查一遍，所以那个分支**唯一**产出的东西是一句话。
断言改成断**那句话**：被拒绝后 HUD 消息要**点出是哪一件**没装下。
否则那句 `if` 会被下一个人当成冗余删掉，而**没人会知道玩家为什么站在一把剑上面捡不起来**。

**② 往返比较是**对称的**，看不见"从来没写过的字段"** ——
删掉 `to_dict` 里的位置，两边都加载到原点、完美一致、绿灯。
修法是拿**标记掉落自己的常量** `DROP_MARK_AT` 比，不是拿两份 payload 互相比。
**和 §45 生产链那条是同一个规矩：拿一个被测对象伪造不出来的东西去比。**

## 已知限制（都写在代码注释里，不是忘了）

1. **掉落只躲开产出它的那个物体。** `_drop_spot` 按**该物体自己的**半对角线让开，
   不管旁边有没有别的东西 —— 一棵树紧贴一块石头时，木头可能落在石头里面。
   现在的世界里资源点间距 ≥ 1.5 m、让开量 ≤ 0.85 m，**发生不了**。
   真要修是"落点先问一遍障碍"，那是另一件事。
2. **落点的 y 就是产出者的 y。** 现在是**全平地**（2026-09-12 明确），
   所以这不是问题；有坡之后要按地形采样。
3. **`refused`（"已经说过装不下"）不进存档。** 读档后玩家会再被说一次。
   它是"这一局说过什么"，不是掉落的属性 —— 重开一局本来就该重新说。
