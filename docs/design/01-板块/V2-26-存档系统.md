## 一句话
存世界事实，不存可以重算的东西。

## 要交付什么
- 保存 Terrain Chunk / BuildingState / ObjectState / NPCState
- **不保存** Mesh、路径、动画等派生结果（§68）
- 加载后由各 Generator 重建一切派生层

## 现有状态

**已完成（2026-09-11）**
- `CozySaveManager`：JSON 写 `user://`，带版本号；**版本不符直接拒绝**而不是半读
- 序列化：地形 / 建筑（墙+楼板+楼梯+id 计数器）/ 世界物体（含容器内容物）/ 居民 / 时钟
- `_apply_world()` 按 `_ready()` 的**同一顺序**重建：地形 → 建筑 → 物体 → 居民，
  再由各 Generator 重建派生层（房间/portal/导航/屋顶）
- F5 存、F9 读

**已完成（2026-09-12）· 存档格式 v2 ＋ 跨进程验证**
- **`VERSION` 2：世界变成一条实体列表**（`{kind, state}`）。v1 是"一个系统一个顶层 section"，
  于是"这个世界里有什么"有几个系统就有几个答案，而 id 只有已经知道谁铸它的读者才解析得了。
  **id 在 payload 里面**；**计数器不是实体**，走 `next_ids`；**派生 kind 在注册处排除**
- **迁移链是可测的**：`_migrations` 从文件版本**逐级走**到 `VERSION`，
  任何一级缺失就**拒绝**（半懂的世界比没有世界更糟 —— 它看起来像读成功了）
- **跨进程验证**：`--cozy-save-on-exit` 改世界→写盘→退出，然后**全新进程**
  `--cozy-load-first` 从默认世界出发读档比对。**单进程断言在结构上够不到这一段**

**已完成（2026-09-16）· 写安全 —— 一次崩溃不能让玩家什么都不剩**

**老写法是 `FileAccess.WRITE` 打开活档路径** —— 它**在新世界写入第一个字节之前就把旧世界截断了**。
那个窗口里崩一次，留下的不是"损坏的世界"，是**没有世界**（`load_world` 返回 `{}`）。
**这不是假设**：探针 `tests/probe/save_write_probe.gd` 造出那个文件并打印
`a truncated save with NO backup: load_world -> {} (the world is GONE)`。

现在是 **写 `.tmp` → 把活档改名成 `.bak` → 把 `.tmp` 改名成活档**，
顺序的道理是**在每一个瞬间，磁盘上至少有一份完整的世代**。
两次改名之间崩掉 → 没有活档、但有一份完整的 `.bak` —— 所以 `load_world` **会去试它**。

**回退不静默**：`CozySaveManager.last_source` 记 `main` / `backup`，走备份会 push_warning。
**一个没人知道的回退不是安全措施** —— 玩家会拿着**落后一档**的世界继续玩，
而且**所有检查都通过**，因为检查问的是"世界回来了没有"，不是"回来的是哪一份"。
残留的 `.tmp` 同理：它是**名字看起来很正常**的半成品，所以**丢弃并说明**，绝不拿来读。

**同一轮挖出 bug 23 的第二次出现**：`_read_doc` 用的是 `JSON.parse_string`，
它**遇到坏文件会直接打印** —— 于是"拒绝一个坏档"看起来和"构建坏了"一模一样。
**bug 23 的修法当时只打在副本蓝图上，存档层一直留着老写法**，两天没人发现，
**因为从来没有测试喂过它一个读不了的文件**。第一个这样的测试把单元运行的
`0 ERROR` 变成 `1 ERROR`，**而每一条检查照样是绿的**。

**量出来的两条平台事实（不是猜的）**：
- **rename 覆盖已存在的目标是可用的**（四种写法都 OK，而且本项目 `user://` 路径**含空格**）——
  但 **Windows 不保证 POSIX 那条保证**，**所以真正的网是那份 `.bak`，不是 rename**
- `FileAccess.flush()` 是 Godot 能给的、最接近 fsync 的东西（**没有目录 fsync**），
  所以断电仍然可能弄丢一份"报告说存成功了"的档 —— **那份 `.bak` 也是为它准备的**

**删掉了 `save_manager.exists()`**：**没有任何调用方**（本项目最贵的那个习惯），
而"有没有档"这个问题 `load_world` 用返回 `{}` 就答了。

**这件事也是 §82 ②「存档边界」的第一半** —— 见 `03-流程/待拍板-C类.md` 第 6 条。

**这块挖出的 bug（已进 INVARIANTS，编号 16/17/18）**
1. **`BuildingState.to_dict()` 只存墙**。一次读档会丢掉**全部楼板和一整段楼梯**。
   而房间是从墙派生的，所以房间数**照样对** —— 世界看起来几乎正常，
   但没人上得了二楼。单帧和肉眼都看不出来。
2. **`JSON.stringify` 不认 `PackedByteArray` 等打包数组，会静默写成字符串**。
   读回来是个 String，赋不回原来的字段。
   而**原有的地形往返断言照样通过** —— 因为它是在**内存里**往返的：
   `to_dict()` 交回的是活的 packed array，赋值成功，断言变绿，而磁盘上的文件根本读不了。
   **不经过文件的往返，证明不了任何关于存档的事。**
3. **`_sync_views` 用 id 匹配视图和 state，从不回指 `v.state`**。
   这只在"state 对象永远不被替换"时才等价于按对象匹配 —— 只增删是可以的，**替换不行**。
   读档会替换全部 state 对象。被墙角断言抓住：角上的几何不再响应解算器。

**未做**
- **世界还没有 id**：路径是写死的 `user://world.json`，所以**一台机器只有一个世界**。
  §82 ①「世界归属」要的就是"世界有 id"；这是欠债 20，也是联机那三步里的第一步
- **没有存档槽 / 没有选档 UI**（与上一条同源）
- **没有自动存档**（Willow 2026-09-16 要）—— 形态待定，社区共识是
  **最多一分钟一次、写进一个单独的自动存档文件、绝不覆盖玩家主动存的那份**，
  而且**只在安全边界**（离开家园 / 日切 / 出副本）
- **没有权威**（单机，谁算世界状态这个问题今天不需要答案）

> 断言做两件独立的事：**事实**要能往返（序列化），**派生层**要从事实重建（再生成）——
> 两者会各自失败。而且它**真的对活世界执行一次读档再把世界放回去**：
> 写了却从没跑过的加载路径，正是这个项目已经付过三次代价的
> "声明了但没有消费者"形状。
>
> 已实测验证牙齿：把 `to_dict` 退回只存墙，报 `8 wall(s) / 0 slab(s) / 0 stair(s)`。

**写安全的牙齿（改坏实验，4 条，脚本在仓库外 `D:\cozy\tools\mutation_check_save.py`）**：

| 改坏 | 断言红 | ERROR |
|---|---|---|
| **写回原地**（2026-09-16 之前的老 bug） | **2** | 9 |
| 换回 `JSON.parse_string` | **0** | **1** ← **只有日志看得见** |
| 不试备份 | 2 | 1 |
| erase 只删主档、留备份 | 2 | 0 |

> ⚠️ **第 2 行要如实读**：那条修法**没有任何断言在看它**，只有"日志干净"在看。
> 这是 bug 23 的形状第二次出现。**不装作有断言盯着。**
