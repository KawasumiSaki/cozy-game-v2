# 副本世界 + 装备/词条/掉落系统 V1.0

## ------最小可运行、纯数据驱动、零世界耦合、可持续扩展的 ARPG 架构

> 项目定位：家园世界 + 可进入的副本世界。
>
> V1.0 只解决一条完整闭环：
>
> **家园 → E 进入副本 → 近战战斗 → 击杀怪物 → 掉落装备 → 拾取 →
> 查看属性/词条 → 装备 → 属性生效 → E 返回家园**
>
> 核心原则：
>
> **装备系统不是战斗系统的子系统，掉落系统不是怪物脚本的子系统。**
>
> 它们都是独立的数据系统，通过极少量接口互相连接。

------------------------------------------------------------------------

第一版不要做完整 Diablo。

只做一个可以玩的垂直切片：

``` text

                     │   [副本入口]  │
                     └──────┬───────┘
                            │ E
                            ↓
                  ┌──────────────────┐
                  │     副本世界      │
                  │                  │
                  │  玩家             │

                  │   ↓              │
```

# 2. 最重要的架构原则

## 2.1 Definition 和 Instance 必须分离

这是整个装备系统最重要的设计。

不要把：

``` text
铁剑
攻击力 10
暴击 5%
火抗 3
```

直接写死成一个物品。

应该分成：

``` text
ItemDefinition
        +
ItemInstance
```

例如：

``` text
ItemDefinition
    id = sword_iron
    type = one_hand_weapon
    base_damage = 10
    level = 1
```

掉落时生成：

``` text
ItemInstance
    definition = sword_iron
    rarity = rare

    affix:
        +4 strength
        +6% attack_speed
        +3 fire_resistance
```

这样同一把"铁剑"可以生成：

``` text
铁剑
+3力量
+4%攻速
```

也可以生成：

``` text
铁剑
+8力量
+7%暴击
+5火抗
```

甚至：

``` text
铁剑
+12力量
+10%攻速
+8%暴击
```

# 3. 三层数据结构

整个系统只需要牢牢记住三层：

``` text
Definition
    ↓
Instance
    ↓
Aggregated Stats
```

## 3.1 Definition

定义"这是什么"。

例如：

``` text
Iron Sword
Leather Armor
Wooden Shield
Fire Ring
Health Potion
```

Definition 是静态数据。

------------------------------------------------------------------------

## 3.2 Instance

定义"你捡到的这一件具体是什么"。

例如：

``` text
Iron Sword #001
rarity = Rare

Strength +5
Attack Speed +7%
Fire Resistance +4%
```

Instance 才拥有随机词条和随机数值。

------------------------------------------------------------------------

## 3.3 Aggregated Stats

定义"装备以后角色最终是多少"。

例如：

``` text
Base:
Attack = 10
HP = 100
Armor = 5

Equipment:
Attack +12
HP +20
Armor +8
Fire Resistance +10%

Final:
Attack = 22
HP = 120
Armor = 13
Fire Resistance = 10%
```

不要在代码里大量写：

``` gdscript

"hp"
"fire_res"
```

``` gdscript
    MAX_HP,
    ATTACK,
    DEFENSE,
    ATTACK_SPEED,
    MOVE_SPEED,
    CRIT_CHANCE,
    CRIT_DAMAGE,

    PHYSICAL_RESISTANCE,
    FIRE_RESISTANCE,

```

``` text

```

# 6. 数值聚合系统

这是整个装备系统最值得认真做的部分。

不要：

``` gdscript
player.attack += item.attack
```

因为以后会越来越乱。

统一走：

``` text
Base Stats
      ↓
Equipment Modifiers
      ↓
Buff Modifiers
      ↓
Debuff Modifiers
      ↓
Final Stats
```

------------------------------------------------------------------------

# 7. Modifier

所有装备词条最后都应该转换成 Modifier。

例如：

``` text
+10 Attack
```

就是：

``` text
Modifier(
    stat = ATTACK,
    operation = FLAT,
    value = 10
)
```

而：

``` text
+10% Attack
```

是：

``` text
Modifier(
    stat = ATTACK,
    operation = PERCENT,
    value = 0.10
)
```

------------------------------------------------------------------------

# 8. Modifier 运算顺序

V1 统一：

``` text
Final = (Base + Flat) × (1 + Percent)
```

例如：

``` text
Base Attack = 20

装备：
+10 Attack
+20% Attack
```

结果：

``` text
(20 + 10) × 1.20
= 36
```

以后如果需要：

``` text
More Damage
Less Damage
Multiplicative Modifier
```

再增加新的 Operation。

V1 不需要。

------------------------------------------------------------------------

# 9. EquipStatCalculator

核心接口：

``` gdscript
func calculate(base_stats: Dictionary, modifiers: Array) -> Dictionary:
```

输入：

``` text
Base Stats
Modifiers
```

输出：

``` text
Final Stats
```

例如：

``` text
Base:
ATTACK = 20
MAX_HP = 100

Modifiers:
ATTACK +10
ATTACK +20%
MAX_HP +30
```

输出：

``` text
ATTACK = 36
MAX_HP = 130
```

这个函数必须：

-   不依赖 Player
-   不依赖 Node
-   不依赖 Scene
-   不依赖 Camera
-   不依赖 World
-   不依赖 UI
-   不依赖 Monster

它就是纯函数/纯逻辑。

# 12. 盾牌系统

盾牌不是普通攻击装备。

V1：

``` text

    如果没有盾牌：

```

``` text

```

``` text

```

或者：

``` text

```

这样以后加入：

``` text

双持
弓
枪

```

# 16. 词条 Roll

词条不是：

``` text
+5
```

而是：

``` text
AffixDefinition
        ↓
Roll
        ↓
AffixInstance
```

例如：

``` text
Definition:
Strength
2 ~ 8
```

随机得到：

``` text
Strength +6
```

Instance：

``` text
affix_id = strength
value = 6
```

------------------------------------------------------------------------

# 17. 词条品质

为了简单又有潜力，使用：

``` text
roll_ratio = (value - min) / (max - min)
```

得到：

``` text
0.0 ~ 1.0
```

可以显示：

``` text
0~30%      Low
30~70%     Normal
70~90%     High
90~100%    Perfect
```

但 V1 不需要额外的颜色和 UI。

系统只保存实际 value。

# 20. 装备生成

装备生成流程：

``` text
ItemDefinition
      ↓
Roll Rarity
      ↓
Determine Affix Count
      ↓
Get Affix Pool
      ↓
Weighted Random Select
      ↓
Roll Affix Values
      ↓
Create ItemInstance
```

例如：

``` text
Iron Sword
      ↓
Rare
      ↓
2 affixes
      ↓
Strength
Attack Speed
      ↓
+6 Strength
+7% Attack Speed
```

# 21. 权重系统

词条不要使用简单等概率。

例如：

``` text
Strength       weight 100
Attack Speed   weight 60
Crit Chance    weight 40
Life Steal     weight 10
```

因此：

``` text
Strength
```

更常见。

``` text
Life Steal
```

更稀有。

这会成为未来 Loot 系统的核心。

# 33. Damage Calculator

伤害计算不要直接写在武器脚本里。

统一：

``` text
DamageCalculator.calculate(
    attacker_stats,
    defender_stats,
    attack_data
)
```

V1：

``` text
Raw Damage = Attack
```

然后：

``` text
Damage × (1 - Resistance)
```

例如：

``` text
Attack = 30
Enemy Physical Resistance = 20%

Damage = 30 × 0.8
       = 24
```

暴击：

``` text
Crit Damage = Damage × Crit Multiplier
```

# 62. 一个非常重要的判断

我们的项目不应该：

> "找一个 Diablo 插件，然后把它改成我们的游戏。"

而应该：

> **建立自己的 Item/Stat/Affix/Loot 数据标准。**

第三方项目只负责：

``` text
参考
```

而不是：

``` text
核心依赖
```

这样以后我们的：

``` text
家园
副本
装备
怪物
建造
任务
世界树
飞艇
```

都可以使用统一的数据架构。

# 65. 最终设计原则

整个系统只坚持 8 条规则：

### 1.

**Definition ≠ Instance**

### 2.

**装备属性全部通过 Modifier 聚合**

### 3.

**StatAggregator 是纯逻辑**

### 4.

**LootTable 不生成 UI**

### 5.

**Monster 不生成装备**

### 6.

**Inventory 不计算战斗属性**

### 7.

**UI 不保存核心游戏数据**

### 8.

**World 只负责表现和交互**

# 67. 最终建议

**现在最值得做的不是把装备系统做"大"，而是把数据边界做"干净"。**

第一版只有：

``` text

8 个 Affix
5 个 Rarity
5~6 个 Item
2 个 Enemy
1 个 Dungeon
```

就足够。

``` text
ItemDefinition
ItemInstance
AffixDefinition
AffixInstance
Modifier
StatAggregator
LootTable
LootRoller
InventoryManager
EquipmentManager
```

这 10 个核心对象之间没有循环依赖。

``` text
+
```
